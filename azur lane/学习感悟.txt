实战踩坑录 (经典编译错误与逻辑漏洞)
1. 常量陷阱 (The Const Correctness Trap)

现象： 头文件声明了 getGlobalBounds() const;，但在 .cpp 文件里漏写了 const，导致出现极其诡异的“无法解析的外部符号”报错。

感悟： C++ 编译器在进行函数签名匹配时，后缀的 const 是签名的一部分。少写一个词，编译器就认为这是两个完全不同的函数。
函数后加 const 就是向编译器保证“我只读不改”，从而使该函数能安全地被常量对象调用，同时提高代码的安全性和可读性。

2. 权限守卫与默认私有 (Access Control)

现象： 外部尝试调用 player->getBullets() 时，爆出红色的“不可访问”。

感悟： 在 C++ 的 class 中，如果不显式写明 public:，所有成员和函数默认都是 private（私有）的。面向对象的核心不仅在于封装数据，更在于精心设计哪些接口应该暴露给全宇宙，哪些必须死死锁在类内部。

3. 头文件循环与多重定义 (LNK4042 & LNK2019)

现象： 报这种LNK错误

感悟：都是编译的问题，大概率是编译器抽风了，这里可以清空解决方案再重新生成一下


4. O(N^2) 的性能黑洞 (渲染逻辑嵌套)

现象： 把画子弹的循环错误地嵌套在了画敌人的循环内部。假设 5 个敌人和 10 颗子弹，导致一帧内子弹被重复渲染了 50 次。

感悟： 这是游戏开发中最容易忽视的性能杀手。渲染层必须严格扁平化和分层（Z-Index），逻辑判断（碰撞检测）可以嵌套，但画面绘制绝对不能互相嵌套。

5. 引用传递的威力 (Pass by Reference)

现象： 在底层更新时传了 int mainScore，导致无论杀多少怪，主界面的分数永远是 0。

感悟： 值传递（Pass by Value）只会复制一个副本进去，出了函数就销毁了。在参数前加一个 & 变成 int& mainScore，就等于接通了内存底层的直达管道，让函数内部可以直接修改外部环境的真实数据。

现代 C++ 核心语法解析
这次项目中深度使用了 C++11/14 的高级特性，这也是未来企业级后端开发面试的绝对核心考点。

1. 独占智能指针 (std::unique_ptr)
在 C 语言或老旧的 C++98 中，开发者必须手动 new 和 delete，只要忘记一次，就会造成内存泄漏，这也是程序崩溃的万恶之源。

核心理念： RAII（资源获取即初始化）。智能指针是一个类，它在构造时接管内存，在超出作用域（被析构）时，自动触发底层的 delete 清理内存。

独占性： unique_ptr 顾名思义，它不允许被复制。这也是为什么之前尝试使用 enemyManager = EnemyManager(); 覆盖时会报错，因为底层数组里的智能指针拒绝被拷贝。我们最终通过调用 clear() 方法，利用智能指针自动释放旧内存的特性，极其优雅地实现了“瞬间重置战场”。

语法范式：

C++
// 永远使用 make_unique 来创建，避免内存碎片和异常安全问题
std::unique_ptr<Player> player = std::make_unique<Player>();
2. Lambda 表达式 (匿名函数)
在处理 STL 算法（如 std::remove_if）时，如果你去外部专门写一个判断函数传进去，会极其破坏代码的连贯性。Lambda 允许你直接在调用点“就地”写一个函数。

基本结构： [捕获列表](参数列表) -> 返回值类型 { 函数体 }

捕获列表 [] 的魔力： 这是 Lambda 最强大的地方。常规函数是无法直接看到外部局部变量的，但 Lambda 可以通过捕获列表把外面的变量“抓”进来用。

[]：什么都不抓，纯粹的内部运算。

[&]：按引用抓取外部所有的局部变量（危险，但极方便）。

[&mainScore]：极其精准地只按引用抓取 mainScore 这一个变量。

项目中的实战应用：

C++
// 配合 remove_if 的擦除-移除惯用法
auto newend = std::remove_if(enemies.begin(), enemies.end(), [&mainScore](const std::unique_ptr<Enemy>& e) {
    if (e->isDead()) {
        mainScore += e->getScoreValue(); // 因为有 [&mainScore]，这里才能修改外面的总分
        return true; // 告诉 remove_if 把这个元素移到末尾准备删除
    }
    return false;
});
